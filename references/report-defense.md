# 报告与答辩

## 报告章节（实际以当届要求为准）

建议结构：摘要与核心发现；背景与问题；文献/理论；调查方案；预测试与正式实施；数据质量；分研究问题建模与解释；可落地结论建议；限制；参考文献；附录与 AI 使用台账。**不能**以往届报告页数或他校要求替代正式提交规则。

## 证据绑定

正文每一条重要论断应有：`结论编号 → 对应研究问题 → 真实表图/计算结果 → 数据来源与口径 → 适用范围和不确定性`。建议包括对象/责任人、具体动作、资源、时间、可观察指标。图表与正文数据不得分歧。

## 答辩

用户只要结构或模拟追问时，可先交付占位大纲和通用问题清单；报告尚未提供则列出需要填入的真实发现和图表，不编造问卷数量、显著性或结果数字。正式 PPT、讲稿和项目专属回答须对照真实报告后再验收。

演示先回答：为什么研究这个问题、数据怎么来、怎样分析、发现是什么、可怎么执行、结论在哪里失效。PPT 优先展示实际图表/访谈原始信息（注意隐私），不创造新数据。演练问题包括抽样代表性、有效问卷标准、统计/因果解释、模型稳健性、商业可行性、调查伦理、AI 使用。保留排练记录与修正点。

## 最终一致性检查

报告数字、论文图表、演讲稿、PPT、结果文件全部对照 `claim_evidence_matrix`。即使 `submission_package_manifest` 存在，也不等于上传成功；由团队提供提交回执，最后才能记为实交。
## 只交付大纲时的状态

大纲保存为 `defense/outline.md`，标记为待填真实结果的草稿。若已初始化，可登记为 `defense_notes`，但 `defense` 阶段继续保持 pending；不把占位大纲登记为真实 `slides`，没有实际演练就不登记 `mock_defense_log`。独立阶段咨询不必为了留痕补造前序通过记录。
