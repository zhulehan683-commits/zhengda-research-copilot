# 获奖题目雷达：先查撞题，再决定选题

这份指南把“公开获奖题目密度”变成一个可重复的选题前检查。它回答的是：**在已知的全国一、二等奖题目里，类似方向出现过多少次、最高拿过什么奖、集中在哪些年份和组别、最接近的题目是什么。**它不回答创新性、可行性、样本可达性或获奖概率。

## 数据口径

- 范围：2022—2026 年正大杯全国一、二等奖题目，共 2,920 条；不含省赛、校赛、三等奖和未获奖作品。
- 字段：年份、届次、组别、奖项、学校、题目、主题大类、细分主题、标签、关键词、分类置信度、待复核标记、公告链接和附件链接。
- 分类来源：第三方根据作品标题自动生成；高 1,883 条、中 614 条、低 423 条。低置信度记录必须人工复核。
- 覆盖缺口：2025 年研究生组，2026 年研究生组、专科组和在华留学生组没有文本型附件，当前快照缺失。空缺格表示“没有记录”，不能解释为“当年无人参赛”或“数量为零”。
- 跨年比较只看本科组：2022—2026 连续完整；其他组别直接混合会把缺失年份误当成下降。

## 默认触发点

出现以下任一情况时，先跑雷达，再给候选题打分：

- 用户问“这个题有没有人做过”“会不会撞题”“哪个方向还是空档”；
- 选题评分表即将定稿，或要从 2—3 个方向中选一个；
- 需要判断某个热词是“刚起步”“稳定有人做”还是“已经拥挤”；
- 要把“没有前人做过”写进研究简报或答辩。

## 三条命令

### 1. 先看离线聚合基线

```powershell
python -X utf8 "<SKILL_ROOT>/scripts/topic_radar.py" baseline
```

它直接读取 `references/award-topics/baseline.json`，显示覆盖矩阵、本科组主题累计、2026 年一等奖主题和关键词信号。**不联网、不读取原始题目、不含 2,920 条明细。**

### 2. 需要具体题目时，由用户显式抓取快照

```powershell
python -X utf8 "<SKILL_ROOT>/scripts/topic_radar.py" fetch --project "<PROJECT_ROOT>"
```

默认写入 `<PROJECT_ROOT>/raw_private/award-topics/data.js`，该目录已在研究工作区 `.gitignore` 中。命令只在用户运行时才下载；默认 URL 固定到上述提交，并校验 SHA-256。也可以：

```powershell
python -X utf8 "<SKILL_ROOT>/scripts/topic_radar.py" fetch --output "D:\my-data\awards_2022_2026.js"
```

上游仓库当前未声明根许可证。**不要把下载的原始快照提交到公共仓库，也不要把 2,920 条题目重新分发。**本仓库只保留人工整理的聚合计数。

### 3. 检索并生成可留痕报告

```powershell
python -X utf8 "<SKILL_ROOT>/scripts/topic_radar.py" search --project "<PROJECT_ROOT>" `
  --query "清洁标签 零添加 配料表 添加剂 食品标签" `
  --write "<PROJECT_ROOT>/plans/topic-density-clean-label.md"
```

常用筛选：

```powershell
# 只看本科组和一等奖
python -X utf8 "<SKILL_ROOT>/scripts/topic_radar.py" search --project "<PROJECT_ROOT>" `
  --query "宠物 主粮 医疗 保险" --group "本科组" --award "一等奖"

# 排除低置信度分类
python -X utf8 "<SKILL_ROOT>/scripts/topic_radar.py" search --project "<PROJECT_ROOT>" `
  --query "低空 无人机" --exclude-low-confidence

# 机器可读输出
python -X utf8 "<SKILL_ROOT>/scripts/topic_radar.py" search --data "D:\my-data\awards_2022_2026.js" `
  --query "AI陪伴 陪伴机器人" --json
```

检索范围是题目、主题、细分主题、标签和关键词的**子串匹配**。中文同义词必须自己补；例如“老人/银发/适老化”“宠物/猫狗/伴侣动物”要分别试。英文建议同时试 `AI`、`人工智能` 和空格变体。

## 怎样读结果

| 看到的结果 | 可以说什么 | 不能说什么 |
| --- | --- | --- |
| 命中 0 条 | “当前快照和查询词下未观察到记录” | “没人做过”“一定是空白” |
| 命中 1—3 条 | “公开一等奖题目中较少见，需人工复核分类和同义词” | “评委一定喜欢”或“容易获奖” |
| 命中 10 条以上 | “已形成可见的题目簇，需要换切面或更强的方法差异” | “数量多就说明不能做” |
| 有同题一等奖 | “该方向曾被评委接受，存在可行先例” | “照做就会再次获奖” |
| 集中在某一年 | “可能是新近升温，也可能是分类或附件覆盖变化” | 直接推断为真实市场趋势 |
| 低置信度记录多 | “结果需逐条人工复核” | 把自动标签计数当作事实 |

数字来自固定快照的标题、主题、标签和关键词字段；同一作品可能同时命中多个词，**不能把各行相加当作总量**。关键词计数也不等于人工确认的主题数量。

## 写回选题评分

把雷达结果的以下内容写进 `templates/topic-scorecard.csv`：

- `topic_density_count`：命中记录数；同时写清筛选范围（例如“全库”或“本科组”）。
- `topic_density_best_award`：一等奖、二等奖或“未观察到”。
- `topic_density_years`：年份分布。
- `topic_density_nearest`：最接近的题目和学校，保留原始链接。
- `topic_density_notes`：同义词、低置信度、覆盖缺口和人工复核结论。

把报告写入项目 `plans/` 后，在 `topic_brief` 或 `feasibility_check` 中引用报告路径、检索日期和完整命令。当前 topic 阶段的机械证据键仍是 `topic_brief` 与 `feasibility_check`，不存在单独的 `topic_density` 键；不要把雷达报告声称为尚未登记的独立证据。雷达报告是选题说明的支撑材料，不是质量认证。

## 边界

- 不是官方评分标准，不保证获奖，不替代研究问题、样本可达性和伦理检查。
- 只统计获奖题目，不统计未获奖投稿；因此“数量少”可能意味着冷门，也可能意味着难做或被淘汰。
- 标题分类会漏掉隐喻式题目和同义表达；自动标签不是人工主题编码。
- 缺失年份不能当作零；跨年趋势先看覆盖矩阵，再看占比。
- 原始快照无明确再分发许可；本仓库不分发题目明细，工具只在用户许可范围内本地读取。
