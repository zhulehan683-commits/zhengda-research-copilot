# Grill Me：研究决策压力测试

本指南适配 [Matt Pocock 的 grill-me / grilling](https://github.com/mattpocock/skills/tree/49dd158d1076134a641b33efb035946536778336/skills/productivity)。上游原文保存在 `references/upstream-skills/`，MIT 许可见 `licenses/mattpocock-skills/LICENSE`。上游 grill-me 只是转调 grilling 的入口；本项目在 `.agents/skills/` 提供含完整行为的研究适配入口。

## 何时使用

用户要求“grill me / 拷问我 / 压力测试选题、抽样或分析方案”时使用。只覆盖用户指定的当前决策；已明确的执行任务直接执行，不自动拉长为全流程访谈。仅讨论时不初始化研究目录；已有项目可只读状态和材料。

在支持原生 Skill 调用的客户端使用本项目 grilling；没有该工具或未发现子技能时，读取 `<SKILL_ROOT>/.agents/skills/grilling/SKILL.md`。适配入口本身包含关键约束，上游原文仅作来源对照。引用路径始终以主技能根目录解析，不以研究目录解析。

## 按依赖关系提问

1. 先读已有材料，把事实、用户已作决定、待查事实和待作决定分开。
2. 为当前目标建立决策树。每轮只问前置条件已确定的节点；例如对象未定时，不先问最终样本配额。
3. 同一轮合并所有当前可回答的问题，每问给出建议及理由，让“同意”能明确对应建议。未知依据标为假设。
4. 等用户答复后再展开依赖其答案的问题；不替用户回答，也不把未回复当默认同意。用户指定一问一答或缩小范围时按其要求调整。
5. 能通过文件或官方来源查到的事实由 Agent 查询。无法查到的私有事实（预算、渠道授权等）才向用户补问；没有子 Agent 时自行查询，不虚报派工。

示例（对象已确定，本轮只讨论可达性）：

> Q1：你们能通过哪些渠道实际联系受访者？建议先列已获准的两个渠道及各自可联系人数，再决定抽样方式。
>
> Q2：单个受访者可接受多长的问卷？建议把完成时间作为预测试需要实测的约束，当前不把经验时长写成赛事要求。

## 正大杯检查点

| 决策分支 | 需要问清的具体问题 | 后续产物 |
| --- | --- | --- |
| 选题 | 谁的什么行为、差异或关系？怎样的结果会推翻设想？ | `templates/research-brief.md` |
| 总体与样本 | 接触框、纳入条件、渠道、不可达群体是什么？可推断到哪里？ | `templates/sampling-plan.md` |
| 测量 | 构念如何操作化？题项时间窗、编码和预测试如何安排？ | 问卷、变量字典、逐题审核表 |
| 分析 | 主要结果、方法前提、排除规则及失败降级是什么？ | `templates/analysis-contract.csv` |
| 结论与行动 | 哪张表/图支撑主张？哪种解释仍无法排除？谁能据此做什么？ | 结果矩阵、报告与答辩问题 |
| 规则与资源 | 当前通知是否适用？谁负责授权、采集、核验和提交？ | 规则核验、团队分工 |

## 结束与交接

问题问完后，用一段新人能读懂的话解释整个研究如何完成，再列已决定事项、待核验事实和剩余风险。此补充借鉴上游 [Issue #893](https://github.com/mattpocock/skills/issues/893) 提出的问题；不把 Issue 的建议声称为已合并的上游行为。

只在本轮范围内确认共识，不追问无关分支。需要现实预测试才能回答的事项记为待验证；不要靠反复提问制造确定性。用户确认后，可把结论写入 Intake、抽样计划或分析合同；阶段放行仍按原有证据门禁进行。达成共识前不改项目状态。
