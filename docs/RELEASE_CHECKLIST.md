# GitHub Release Checklist

在公开仓库或发布版本前逐项确认：

## 项目完整性
- [ ] `SKILL.md` frontmatter 与引用路径正确；
- [ ] README 的安装路径、命令和功能描述与当前代码一致；
- [ ] `CHANGELOG.md` 记录了本次变更；
- [x] Windows PowerShell 安装脚本已在实际 Windows/PowerShell 环境测试（2026-10-17，新目录安装及 50 个文件哈希核对通过）；
- [ ] Python CLI 与测试已在声明支持的 Python 版本运行；
- [ ] ZIP 解压后文件结构与源目录一致。

## 安全与隐私
- [ ] 不含真实受访者数据、私密问卷、个人信息、账号凭证、密钥或 `.env`；
- [ ] 检查 `git status`、`git diff --check` 和待提交文件列表；
- [ ] 原始数据目录、状态日志和任务日志不会被误提交；
- [ ] 没有把样本/统计示例包装成真实参赛结果。

## 规则与研究诚信
- [ ] 当届主办方规则、学校通知和赛区要求已按适用范围分别核验；
- [ ] 不把其他学校的报名代码、截止日期或提交格式当作通用规则；
- [ ] AI 使用披露、匿名、地图和报告格式按当届要求检查；
- [ ] 结论、图表、PPT 和答辩内容可以追溯到数据、代码和来源。

## 第三方与许可
- [ ] 逐个核对上游仓库许可证和再分发边界；
- [ ] `THIRD_PARTY_NOTICES.md` 与实际分发文件一致；
- [ ] 项目所有者已确认许可证，并添加标准 `LICENSE` 文件；
- [ ] README 没有虚假 CI/覆盖率徽章、虚假测试结论或不实的自动化承诺。

## 发布流程建议
1. 先推送到私有 GitHub 仓库；
2. 运行自动化测试和人工审查；
3. 检查首次 Commit 与 Git 历史，避免敏感信息曾被提交；
4. 由所有者确认许可证后再公开；
5. 创建 Release 前记录版本、变更、测试环境和已知限制。
