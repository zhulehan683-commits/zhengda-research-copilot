# Project Specification — Market Survey Competition

> 本文件是产品范围与验收标准的单一说明源。它描述项目应做什么，不把规划中的功能当作已实现功能。

## 1. 项目定位

`market-survey-competition` 是面向大学生市场调查与分析竞赛的中文优先 Agent Skill。第一个竞赛配置为“正大杯”全国大学生市场调查与分析大赛第十七届（2026–2027）。设计目标是把竞赛准备、真实调查、统计分析、研究报告、答辩与提交审核组织成有证据、可恢复、可交接的工作流。

它是研究辅助和项目协调工具，不是竞赛主办方产品，不保证获奖，也不替代参赛者完成考试、真实调查、学术判断或正式提交。

## 2. 目标用户与任务

- 正在准备正大杯的本科生及团队；
- 需要把市场研究、问卷设计、抽样、统计分析与报告组织在同一项目中的学生；
- 使用 Codex 等 Agent，并希望未来将研究任务交给不同执行 Agent 的团队。

主要任务：

1. 识别当前竞赛阶段和缺失证据；
2. 规划选题与研究问题，形成可执行的调查设计；
3. 记录真实调查过程、数据来源、数据版本和清洗决策；
4. 选择适配研究问题与数据类型的统计方法，保留可复现代码和诊断；
5. 将结论、图表、来源和限制绑定，生成报告与答辩交接材料；
6. 在提交前按当届官方和本校规则检查材料；
7. 通过任务编号、产物哈希、验收条款和独立复核记录支持多 Agent 交接。

## 3. 13 阶段工作流

1. `registration` — 核验当届与本校通知、本人报名状态；
2. `knowledge` — 学习调查统计知识并准备个人知识赛；
3. `team` — 核验组队资格、成员与分工；
4. `topic` — 比较备选题目、研究价值和可行性；
5. `desk_research` — 文献、政策、行业和二手数据研究；
6. `design` — 研究问题、变量、问卷、抽样和伦理设计；
7. `pilot` — 真实预测试、记录问题与修订；
8. `fieldwork` — 团队实际实施调查并保留来源记录；
9. `cleaning` — 预先定义清洗规则，记录排除、缺失和编码；
10. `analysis` — 统计建模、诊断、稳健性检查和独立复现；
11. `report` — 研究报告、证据映射、规则核验与 AI 使用记录；
12. `defense` — 从已核验结果制作 PPT、讲稿和模拟问答；
13. `submission` — 检查提交包并记录由参赛团队取得的回执。

每个阶段都有最低证据清单。机械门禁只能验证文件、路径、哈希与前序状态，不能独自判定研究质量或官方规则合规。

## 4. 架构与状态

- `SKILL.md`：Agent 入口、行为约束和工作流路由；
- `competitions/`：按届次维护的规则基线；
- `references/`：阶段、方法、质量门禁、隐私和 Agent 协作协议；
- `scripts/workflow.py`：本地项目初始化、证据登记、哈希检查、阶段门禁和人工复核留痕；
- `scripts/task_queue.py`：本地任务创建、认领、提交、复核和返工状态；
- `state/project.json` 与事件日志：每个研究工作区的状态和事件；
- `templates/`：选题、问卷、数据、分析、报告、答辩和提交记录模板。

本地脚本没有后台守护进程，不会主动调用 Hermes、Codex、DSH、Workbud 或其他 Agent。只有外部编排器真实调用执行端、收集日志与产物、独立复核并更新状态后，才能声称自动协作闭环已验证。

## 5. 多 Agent 协议

建议角色映射：

- Hermes：可选全局统筹；
- Codex：主控 Skill、任务拆分和状态协调；
- DSH：可选数据处理、代码执行与复现；
- Workbud：可选报告、图表和演示材料；
- Independent Reviewer：未参与被审工件编写的独立审查者。

交接至少记录 `task_id`、阶段、任务目标、输入路径与 SHA-256、负责人、验收条款及其 SHA-256、执行命令、退出码、输出路径与 SHA-256、审查者、审查结论、返工记录和状态更新时间。执行 Agent 不直接改权威项目状态；由单一协调者更新。多机器协作和身份真实性需要外部系统支持，当前脚本不提供身份认证。

## 6. 真实性、伦理与安全要求

- 不得伪造问卷、样本、回收率、访谈原话、来源、模型系数、显著性或提交回执；
- 模拟数据必须清晰标注，不可混入正式参赛结果；
- 研究方法应由研究问题、测量尺度、抽样设计、样本量和数据条件决定，不为凑模型而使用 SEM、聚类或词云；
- 便利样本不得被描述成概率样本或总体代表性样本；
- 原始受访者信息存放于私有目录，默认不进入 Git；向外部 Agent 传递前先做授权检查和脱敏；
- 尊重知情同意、自愿参与、数据最小化、保存期限和适用法律；
- 当届主办方规则与本校/赛区通知优先于经验材料；不能把其他学校的报名代码、截止时间或提交要求套用到用户学校；
- AI 使用方式应按当届规则记录与披露；
- 正式结论、图表、PPT 和答辩内容必须源自已核验数据和分析结果。

## 7. 可选外部 Skill

外部 Skill 只作为按需参考，不随本仓库自动安装，也不保证在运行环境中可发现。主控应先检查是否已安装、当前说明和许可证；若不可用，则按本项目工作流完成任务，不得声称已调用。

路由详见 [`../references/integrations.md`](../references/integrations.md)。

## 8. 明确不在当前实现范围内

- 自动报名、自动缴费、代参加知识赛或自动提交竞赛作品；
- 自动招募受访者、代替团队开展真实调查或伪造数据；
- 内置通用联网研究代理或保证来源真实的爬虫；
- 自动安装/调用所有第三方 Skill；
- Hermes/DSH/Workbud 的真实 API 连接、常驻调度、跨机器锁和身份认证；
- 自动证明某项研究科学、某位 reviewer 真实独立或某作品达到获奖水平。

## 9. 验收标准

每次发布至少应满足：

- Skill frontmatter 与引用路径正确；
- Python 脚本使用标准库，在声明的 Python 版本运行；
- 初始化不会覆盖现有项目；
- 路径穿越和符号链接不能绕过证据目录边界；
- 已登记文件变更后，相关阶段及下游阶段不能沿用旧验收；
- 缺少证据或前序阶段未通过时，门禁阻断；
- 作者不能在本地协议中自审；
- 任务提交不等于验收通过；验收条款或输出变更会阻断签收；
- 文档准确区分机械检查、人工复核和真实 Agent 自动化；
- 发布包不含私有调查数据、密钥或未经授权的第三方内容；
- 许可证在公开发布前由项目所有者明确选择。
